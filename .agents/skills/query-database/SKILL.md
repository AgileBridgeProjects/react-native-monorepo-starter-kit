# Query Database (psql)

The project uses the `psql` CLI to query the development PostgreSQL database.
There is **no MCP server** — run `psql` commands directly in the terminal.

---

## Prerequisites

`psql` must be installed (required for all devs — not optional):

| Platform | Install |
|---|---|
| Windows | `winget install PostgreSQL.psql` |
| macOS | `brew install libpq && brew link --force libpq` |
| Linux | `sudo apt-get install postgresql-client` |

Verify: `psql --version`

---

## Connection details

Connection details live in `.env.local`. The standard `PG*` env vars are set there
and are read automatically by `psql` — no extra flags needed.

```ini
PGHOST=localhost
PGPORT=5432
PGUSER=postgres
PGPASSWORD=<password>
PGDATABASE=starterkit
```

Alternatively a single connection string can be used:
`Host=localhost;Port=5432;Database=starterkit;Username=postgres;Password=<password>`.

---

## Running queries

Load `.env.local` into the shell before running `psql` so the env vars are available:

```bash
# Load .env.local (bash / Git Bash / WSL)
set -a && source .env.local && set +a

# Simple inline query
psql -c "SELECT * FROM players LIMIT 10"

# Override the database explicitly
psql -d starterkit -c "SELECT COUNT(*) FROM matches"

# Multi-line / complex queries — use a heredoc
psql -c "
  SELECT p.id, p.name, COUNT(m.id) AS match_count
  FROM players p
  LEFT JOIN player_matches m ON m.player_id = p.id
  GROUP BY p.id, p.name
  ORDER BY match_count DESC
"

# Connect via an explicit connection URI (Azure / staging)
PGPASSWORD="$DB_PASSWORD" psql "postgres://postgres@localhost:5432/starterkit?sslmode=require" -c "SELECT 1"
```

> PostgreSQL folds unquoted identifiers to lower case, so tables generated by EF Core
> with `PascalCase` names must be double-quoted, e.g. `SELECT * FROM "Players"`.

## Common flags

| Flag | Purpose |
|---|---|
| `-c "<query>"` | Run query and exit |
| `-d <database>` | Override database |
| `-A` | Unaligned output (good for CSV-style export) |
| `-F ","` | Field separator (pair with `-A` for CSV) |
| `-t` | Tuples only — suppress header and row-count footer |
| `-o <file>.csv` | Write output to file |
| `--csv` | CSV output mode |
| `sslmode=require` (in URI) | Force TLS encryption (Azure / staging) |

---

## Safety rules

1. **Prefer read-only queries** — `SELECT` only unless the task explicitly requires a write.
2. **Always confirm destructive operations** with the user before running `DELETE`, `UPDATE`, or `DROP`.
3. **Never log passwords** — do not echo `$PGPASSWORD` or print `.env.local` contents.
4. **Local dev only** — never connect to staging or prod without explicit user instruction.

---

## Troubleshooting

**"psql: command not found"** — Install `psql` (see Prerequisites above).

**"password authentication failed"** — Check `.env.local` values. For the local Docker DB the
password is in `infra/supabase/.env` as `POSTGRES_PASSWORD`.

**"could not connect to server" / connection refused** — Ensure the PostgreSQL container is
running (`docker-compose up`) and `PGPORT=5432` matches the mapped port.

**"database ... does not exist"** — Ensure `PGDATABASE=starterkit` is set and the database exists.
Run `psql -c "SELECT datname FROM pg_database"` to list available databases.

**TLS / SSL error against a managed server** — Append `?sslmode=require` to the connection URI
(Azure Database for PostgreSQL requires SSL).
