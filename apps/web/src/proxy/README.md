# Proxy Layer — Web API

> **AUTO-GENERATED — do not edit files in this directory.**
>
> All TypeScript types, enums, and axios service functions are generated by
> [Orval](https://orval.dev/) from the committed OpenAPI schema.

## Directory layout

```text
src/proxy/
  models/       ← DTOs, enums, request/response types
  services/     ← Axios functions grouped by controller tag
```

## How to regenerate

```bash
# Full: fetch latest schema from running backend → generate → format
npm run generate:proxy

# Local-only: re-generate from the committed schema (no backend required)
npm run generate:proxy:local
```

### Prerequisites for `generate:proxy`

The WebApi must be running on `http://localhost:5002` (or pass `--url`):

```bash
cd apps/backend/src/StarterKit.WebApi && dotnet run
```

## How it works

1. `scripts/fetch-openapi.mjs` downloads `/openapi/v1.json` from the running
   WebApi and saves it to `openapi/web-api.json`.
2. Orval reads the committed schema and generates typed axios functions and
   TypeScript models into `src/proxy/`.
3. Every generated function delegates to the project's shared `apiClient`
   singleton via the custom mutator at `src/lib/http/orval-mutator.ts`, so
   they share the same base URL and default headers. Add interceptors
   (auth, error normalisation) to `apiClient` as the web app matures.
4. Biome formats the output.

## Usage in feature code

```ts
import { getHealthz } from '@/proxy/services/starterkit-webapi/starterkit-webapi';

const health = await getHealthz();
```

## Rules

- **Never hand-edit** files in `src/proxy/` — they will be overwritten on the
  next regeneration.
- **Commit the schema** (`openapi/web-api.json`) so proxy generation is
  reproducible without a running backend.
- When a backend endpoint changes, run `npm run generate:proxy` and commit the
  updated schema + generated files together.
